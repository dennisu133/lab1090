# The `lab1090` SigMF extension, version 1.0.0

lab1090 (`--record`) saves an RTL-SDR's raw samples at 1090 MHz in a SigMF archive, compressed
with zstd (`archive.ts` has the layout). This namespace holds what SigMF's `core` has no field
for: the dongle's settings and what lab1090's demodulator made of the samples while they were
recorded, so a recording can be judged before it is played back.

Fields are only ever added (a minor version), never renamed or given another meaning: every
recording ever made must still read. Readers ignore fields they don't know. A field whose
value isn't known is left out.

## `global`

| Name                      | Type    | Meaning                                                                                                                             |
| ------------------------- | ------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| `lab1090:label`           | string  | What the person recording called it (`--label`): letters, digits, `-`, `_`                                                          |
| `lab1090:source`          | string  | How the samples came: `rtl_sdr` (the dongle on the recording machine) or `rtl_tcp` (one on another machine, over the network)       |
| `lab1090:tuner`           | string  | The tuner chip, as rtl_sdr names it (`Rafael Micro R820T`) or rtl_tcp's header numbers it                                           |
| `lab1090:gain_db`         | number  | The tuner's gain, dB: rtl_sdr's confirmation, else what lab1090 asked for                                                           |
| `lab1090:planned_samples` | integer | Samples (I/Q pairs) asked for (`--record-for`)                                                                                      |
| `lab1090:samples`         | integer | Samples in the dataset                                                                                                              |
| `lab1090:stopped`         | string  | Why the recording ended before `planned_samples`, in words (lab1090 was stopped, the disk was full …)                               |
| `lab1090:messages`        | integer | Mode S messages lab1090's demodulator passed on during the recording, repaired ones included                                        |
| `lab1090:candidates`      | integer | Places that passed its quick preamble test                                                                                          |
| `lab1090:clipped`         | integer | Messages with a sample at the ADC's limit (too much gain, or a very strong signal)                                                  |
| `lab1090:noise_dbfs`      | number  | Mean magnitude of the samples, dB below full scale: mostly the noise                                                                |
| `lab1090:lost_ms`         | integer | Samples lost between the dongle and lab1090 during the recording, as time. They are missing from the dataset, without a new capture |
| `lab1090:ppm`             | number  | The dongle crystal's error, parts per million (+: fast), as lab1090 measured it against the computer's clock                        |

The demodulator's numbers are its own, from the lab1090 version in `core:recorder`: another
version (or readsb) reading the same samples finds a different number of messages, which is
what the recordings are for.

## `captures`

No fields of its own. A new capture segment starts wherever the samples broke off and
started again (rtl_sdr restarted, rtl_tcp reconnected), with its `core:datetime`.
